# EverFlow Experience — Website

Static website for [everflowexperience.com](https://everflowexperience.com): tailor-made ski and
mountain trips, based in Munich, hosted across the Alps.
Served with **GitHub Pages** from the `master` branch. No framework, no server: plain HTML, CSS
and JavaScript, generated from the content files by one small Python script.

`master` is the live site. Change it only through a pull request; the checks below run on every PR.

## Structure

```
├── content/                   # EVERYTHING the site says: edit here
│   ├── site.json              # name, brand line, contact, legal dates, extra photo credits
│   ├── pages.json             # texts of home, about, enquiry, how it works, FAQ
│   ├── destinations.json      # countries and places (facts, who / when / how)
│   ├── partners.json          # hotels and chalets: texts, photos, credit line, place
│   ├── experiences.json       # the nine experiences
│   ├── guides.json            # the guides (English only): sections, places and hotels they name
│   ├── team.json              # the team
│   ├── i18n/es.json, pt.json  # Spanish and Portuguese: each English text → its translation
│   └── legal/                 # Impressum and Datenschutz texts (German / English)
├── scripts/
│   ├── build.py               # content/ → the HTML pages (standard library only)
│   ├── photos.py              # original photo → WebP files for the site (needs Pillow)
│   ├── check.py               # site checks (also run in CI)
│   └── library.py             # the hotel library (local tool, see CLAUDE.md)
├── index.html, 404.html, impressum.html, datenschutz.html,
│   destinations/, stay/, experiences/, guides/, about/, enquire/, es/, pt/, sitemap.xml, robots.txt
│                              # GENERATED by scripts/build.py: never edit them by hand
├── assets/
│   ├── css/everflow.css       # the one stylesheet (tokens in :root)
│   ├── js/everflow.js         # menu, galleries (a photo opens large), enquiry form, click-to-load map, home video
│   ├── fonts/                 # Playfair Display + Public Sans, self-hosted (SIL OFL)
│   ├── vendor/leaflet/        # Leaflet 1.9.4 (BSD-2), loaded only after "Show map"
│   ├── img/                   # WebP files written by scripts/photos.py
│   │   └── stays/<partner>/   # partner photos, each shown with the partner's "©" credit
│   ├── stays/<partner>/       # partner brochures, unmodified, only with written permission
│   └── video/hero-1080.mp4    # home video, original quality (tablets and larger screens only)
├── brand/                     # source files of the logo (scripts/photos.py brand)
├── docs/HOTEL_MATERIAL.md     # which partners are shown, on which basis, with which credit
├── CLAUDE.md                  # rules for Claude sessions in this repo
└── .claude/skills/hotels/     # the steps for a hotel question, a partner page, an offer
```

## Editing

1. Change the text in `content/*.json` (or the layout in `scripts/build.py`, the look in
   `assets/css/everflow.css`).
2. `python scripts/build.py` writes the pages.
3. `python scripts/check.py` must end with `0 failures`.
4. Preview: `python -m http.server` in the repo folder, then open http://localhost:8000.
   (Links start with `/`, so opening the files directly does not work.)

A new photo: `uv run --with pillow python scripts/photos.py site <original> assets/img/<folder>/<name>`.
It writes up to three sizes (800, 1600, 2400 px, never larger than the original); the browser picks
the one the screen needs, so phones stay fast and large screens get a sharp photo. Every photo is
logged with its original in the library folder (outside the repo): `photos.py rebuild` redoes them
all, for instance after a change of quality.
A partner's photo: `uv run --with pillow python scripts/photos.py stay <partner> <name> <original>`;
it refuses when the permission register does not allow photos of that partner.

A guide (`content/guides.json`, English only) is running text plus cards of the places and the
hotels and chalets it names; the destination pages it lists under `related` link to it. A guide
states what the destination and partner pages already state, or plain general knowledge: a new
fact about a hotel goes on its partner page first, checked against the hotel's material.

## Languages

The home page, the destinations and the enquiry form also exist in Spanish (`/es/`, Latin
American Spanish) and Portuguese (`/pt/`, Brazilian), for the guests and agencies who write from
Argentina and Brazil. The other pages (where to stay, experiences, about, the partner pages, the
legal pages) are English only; their language switch leads to the Spanish or Portuguese home page.

`content/i18n/es.json` and `pt.json` map each English text of those pages to its translation.
A new or changed English text has no translation until it is added: the page shows it in English
meanwhile, and `scripts/check.py` warns. To add the missing ones:

1. `python scripts/build.py --missing missing.json` lists them (`missing.json` is a scratch file;
   do not commit it).
2. Translate them with DeepL (target `ES-419` and `PT-BR`). Names stay as they are (Lech am
   Arlberg, Seefeld in Tirol, Les 3 Vallées, Ski Arlberg); only Munich becomes Múnich / Munique.
   `{name}`-style placeholders, `[links](/…)` and numbers stay unchanged; Spanish writes thousands
   with a point (1.300 m) and decimals with a comma (1,5 horas).
3. Add them to the two files, then `python scripts/build.py` and `python scripts/check.py`.

A translation that no page uses any more is a warning too: remove it. The Spanish and Portuguese
pages follow the same wording rules as the English ones: `scripts/check.py` fails on
reserva/reservar and comisión/comissão there.

## Rules the site follows

- **Zero third-party requests on page load.** Fonts, scripts, photos and the video are served
  from this repo; a Content-Security-Policy on every page enforces it in the browser. The only
  external request is the map tiles (OpenStreetMap), and only after the visitor clicks "Show
  map". No cookies, no tracking, no cookie banner.
- **Partner photos carry their owner's credit.** Every photo of a hotel or chalet sits in a
  figure with "© <credit line>" under it, and every credit line is listed in the Impressum.
  `scripts/check.py` fails otherwise.
- **No prices, no booking or payment on the site.** The enquiry form opens the visitor's own
  e-mail or WhatsApp with the message ready; nothing is stored. `scripts/check.py` fails on a
  price or on booking wording.
- **Legal pages stay current.** A change of address, tax status, tool or provider goes into
  `content/legal/` together with a new date in `content/site.json`.
- **The repository is public, the hotel library is not.** The material the partners sent, its
  searchable text and the permission register live outside the repository; `scripts/check.py`
  fails if one of those files is in it, or if a text file holds a Drive path, a local path or
  an e-mail address other than the site's own.

## Checks

`python scripts/check.py` (also in GitHub Actions on every pull request and push to `master`):
the pages match the content, every link, image and anchor resolves, nothing loads from another
host, every page has one `<h1>` and labelled form fields, images are under 950 KB without
metadata, partner photos are credited, the sitemap is complete, every language version a page
names exists, and nothing internal is in the repository. It warns about texts without a
translation and translations nothing uses.
